# Existing dbt, DuckDB, and Cloudflare integration work

Research date: October 13, 2026. Question: has anyone already started the proposed dbt/DuckDB runner and its Basin write path?

**Yes. There is stronger evidence than the initial assessment captured:** a dbt project collaborator reports successful live Cloudflare R2 Data Catalog integration in the upstream Rust dbt implementation, and a separate community project implements a dbt runner on Cloudflare Sandbox. These are useful foundations; they do not establish a complete Dagflare implementation or a tested combination of both projects. The older R2 Data Catalog name in the issues refers to the product now called Basin Catalog. [Naming source](https://github.com/cloudflare/cloudflare-docs/blob/f00bec2e4a282dce209c83ce5ad43001706ee2fb/src/content/docs/basin-catalog/index.mdx)

## Upstream dbt supports the catalog path

The dbt Labs repository's [Cloudflare R2 integration issue #15266](https://github.com/dbt-labs/dbt/issues/15266) was closed on July 29, 2026. Collaborator `dataders` states: “verified working against a live Cloudflare R2 Data Catalog.” Its existing `iceberg_rest` catalog type accepts `endpoint`, `warehouse`, and a DuckDB bearer-token secret referenced with `secret:`; the closure reports no schema or adapter changes were needed. This is explicit live-account integration evidence, rather than a generic Iceberg example. [Closure and qualification](https://github.com/dbt-labs/dbt/issues/15266#issuecomment-5120094469)

The associated [provider-support epic #15265](https://github.com/dbt-labs/dbt/issues/15265) says the catalog-aware runtime and write strategies had landed on `main`. Current source independently shows Iceberg `ATTACH` construction with `SECRET`, `ENDPOINT`, the warehouse name, and `READ_ONLY false` by default. Generic catalog fixtures verify generated SQL; they are not live Cloudflare integration tests. [Implementation](https://github.com/dbt-labs/dbt/blob/b5490800dc93a7496cc17571168182cfd7b16ea2/crates/dbt-adapter/src/engine/duckdb_attach.rs#L163), [fixture](https://github.com/dbt-labs/dbt/blob/b5490800dc93a7496cc17571168182cfd7b16ea2/crates/dbt-adapter/tests/duckdb_attach_fixtures/iceberg_rest_full_options/catalogs.yml), [fixture scope](https://github.com/dbt-labs/dbt/blob/b5490800dc93a7496cc17571168182cfd7b16ea2/crates/dbt-adapter/tests/duckdb_attach_fixtures/README.md)

**Version distinction matters.** That repository's `main` is now Rust dbt v2.0; Python dbt v1 development is on `1.latest`. Its README distinguishes Apache 2.0 repository source from the published dbt distribution's product license. These findings do not prove that our installed Python `dbt-core`/`dbt-duckdb` stack has the same catalog behavior, or identify a released binary with this exact integration. Pin and evaluate a suitable build and its distribution terms before choosing the runner. [Repository README](https://github.com/dbt-labs/dbt/blob/b5490800dc93a7496cc17571168182cfd7b16ea2/README.md)

## Python dbt-duckdb has a different maturity level

The built-in `iceberg` plugin delegates catalog loading and table scans to PyIceberg and returns Arrow data. It implements **source reads only**: there is no `store` override, and the base implementation raises `NotImplementedError`. Its functional test is skipped and cites the maintainer's personal credentials. We found no Cloudflare-specific example in that checkout. [Plugin](https://github.com/duckdb/dbt-duckdb/blob/ef78e1fb15caf7f5f0935d7baa1ae29c18760ddb/dbt/adapters/duckdb/plugins/iceberg.py), [base interface](https://github.com/duckdb/dbt-duckdb/blob/ef78e1fb15caf7f5f0935d7baa1ae29c18760ddb/dbt/adapters/duckdb/plugins/__init__.py), [skipped test](https://github.com/duckdb/dbt-duckdb/blob/ef78e1fb15caf7f5f0935d7baa1ae29c18760ddb/tests/functional/plugins/test_iceberg.py)

That does not rule out writes through DuckDB's native Iceberg extension. Users are already attempting that route. A June 2026 report describes successful full-refresh writes to Polaris using custom schema naming and a drop-then-create materialization, with reduced atomicity; the default replacement lifecycle failed. Other reports cover metadata-query delays and schema naming. These concern other catalogs and older adapter versions, so they identify validation cases rather than establish Basin failures. [Write-path report](https://github.com/duckdb/dbt-duckdb/issues/639#issuecomment-4593689284), [metadata delays](https://github.com/duckdb/dbt-duckdb/issues/640), [schema naming](https://github.com/duckdb/dbt-duckdb/issues/754)

## A Cloudflare-hosted runner already exists

The community [mynkpdr/dbtrunner](https://github.com/mynkpdr/dbtrunner/tree/4a800cd7d5bc9a96102493a0d32f099a444f4348) project provides an MIT-licensed precedent for executing dbt in Cloudflare Sandbox. Its image installs Python, dbt-core, dbt-duckdb, and DuckDB. The Worker creates a sandbox for a run, extracts an uploaded project, streams dbt commands, and destroys the sandbox afterwards. Its README describes Google authentication and streamed run output. The inspected code does not configure Basin or Iceberg, so it demonstrates runner plumbing rather than the catalog integration. [Dockerfile](https://github.com/mynkpdr/dbtrunner/blob/4a800cd7d5bc9a96102493a0d32f099a444f4348/Dockerfile), [source tree](https://github.com/mynkpdr/dbtrunner/tree/4a800cd7d5bc9a96102493a0d32f099a444f4348/src)

## Implication for Dagflare

Evaluate the existing upstream dbt v2/DuckDB catalog path first, and use the Sandbox runner as a deployment reference. Preserve the requirement that the complete installation runs in each team's own Cloudflare account. Prove the chosen versions with dependent models, replacement, supported incremental behavior, tests, artifact capture, failures, and retry reconciliation against a dedicated Basin catalog before declaring the integration ready. The live integration issue retains a generic DuckDB restriction on `DELETE` for partitioned Iceberg tables. [Cloudflare's DuckDB example](https://github.com/cloudflare/cloudflare-docs/blob/f00bec2e4a282dce209c83ce5ad43001706ee2fb/src/content/docs/basin-catalog/config-examples/duckdb.mdx), [remaining Dagflare acceptance gates](../design/validation-plan.md)

This investigation performed source and issue inspection. It did not deploy a Cloudflare runner, access a live Basin catalog, or reproduce the upstream live test in our account.
